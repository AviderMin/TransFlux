# TransFlux 开发文档

版本：1.0 · 日期：2026-10-31 · 状态：待编码的设计基线。

## 交付目的

本包供其他 AI 或开发者直接执行，实现一款以 WinUI 3 Reactor 为不可替换核心、易用且性能可测的本地媒体转换软件。范围包括产品、交互、架构、媒体管线、硬件、数据契约、质量、发布和交接；不包含已运行的程序、已测性能或已锁定的依赖清单。

“必须”是交付约束；“默认”是可配置的初始行为；“目标”必须经实测才可宣称达成；“待验证”需要留下证据，不能以推测替代。文档内示例类型和命令是应用设计契约，不保证为已验证的库 API 或可直接发布的配置。

## 一致性规则

1. 用户明确要求优先于本文档；产品范围以 01/02 为准，交互以 03 为准，媒体规则以 05 为准，状态和持久化以 07 为准。
2. 任何改变框架、默认质量策略、输出保护、许可证路线的提议，都必须新增决策记录并说明影响，不能静默替换。
3. 技术验证结果写入 `docs/evidence/`；本次未创建任何虚构验证报告。新发现与原设计冲突时，先更新相关规范，再编码。
4. 路线图中的 P0 是首个可验收版本，P1 是后续版本；不能把 P1 半成品混入首发主流程。
5. 记录精确 SDK、模板、NuGet、Windows App SDK、Reactor、FFmpeg 版本、来源与哈希；不使用浮动版本或“最新版”作为可复现基线。

## 全局完成标准

从干净机器安装应用后，用户可以离线导入本地文件、选择已验证的预设、执行批量转换、取消或重试、查看结果；异常退出不会损坏源文件或把残缺输出当成功。所有主要页面确由 Microsoft.UI.Reactor 组件生成原生 WinUI 3 控件，硬件能力展示与实际任务路径一致。必须同时提交测试结果、性能报告、第三方许可材料和新的交接记录。
