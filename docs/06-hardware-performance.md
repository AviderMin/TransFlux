# 06 · 软硬件结合与性能

## 能力模型

设备名称只能说明枚举到了硬件。能力必须区分 **编译存在 → 设备存在 → 驱动可初始化 → 特定 profile/像素格式可用 → 完整路径试跑成功 → 当前有资源**。不将 `-hwaccels`、WMI 名称或显卡型号表当作已验证能力。

硬件流水线分为解码、滤镜、编码三段：CPU→CPU→CPU，CPU→CPU→GPU，GPU→GPU→GPU，GPU→CPU→GPU。界面展示实际路径；任何下载/上传都计入性能成本。NVIDIA 官方材料也强调编解码能力依赖具体硬件，不能对全系列统一承诺。[NVIDIA FFmpeg 资料](https://developer.nvidia.com/ffmpeg)

## 探测策略

1. 启动只加载缓存与核心身份，不阻塞 UI；用户开始转换前完成必要探测。
2. 使用 DXGI 等 Windows API 获取适配器 LUID、vendor/deviceId、驱动版本、内存等；软件适配器单独标记。WMI 可补充展示，不能决定支持性。
3. 从固定 FFmpeg 构建读取 encoders/decoders/filters/hwaccels 与相关 encoder help。
4. 针对选中设备，以自生成的小 SDR 样片测试 H.264 编码；有硬件解码/滤镜需求时再测完整路径，超时终止。
5. 试跑要用目标分辨率/像素格式/profile 能力族；低分辨率 8-bit 通过不推断 4K/10-bit 通过。任务启动仍检查会话/显存/驱动错误。
6. 保存结果及 failure reason；缓存键含 coreHash + OS build + adapter LUID/deviceId + driverVersion + probeSchemaVersion + capabilityKey。驱动/核心变化、设备移除、手动重测时失效。

主动探测同一时刻最多一个，单个初始超时 10 秒、总初始预算 30 秒；超时标未知，可手动重试，不标永久不支持。探测过程受同一进程管理，不能启动无主的测试进程。

## 候选路径与选择

| 后端 | 首发路径 | 待验证路径 |
|---|---|---|
| CPU | 软件解码 + CPU 滤镜 + libx264 | 不在首发引入其他软件视频编码器 |
| NVIDIA | 软件解码 + CPU 滤镜 + h264_nvenc | CUDA/D3D11 解码与设备内滤镜 |
| Intel | 软件解码 + CPU 滤镜 + h264_qsv | QSV 解码 + vpp 等完整链 |
| AMD | 软件解码 + CPU 滤镜 + h264_amf | D3D11 解码及兼容设备帧链 |

设备索引在不同 API 间不可互换。LUID 是应用标识，adapterId 到 FFmpeg `gpu`/device 参数的映射由对应 backend 实测建立；不能把“DXGI 的第 1 张卡”直接作为所有编码器的索引 1。

自动策略先排除不满足媒体约束、质量档或设备可用性的候选，再考虑测得的吞吐、传输开销、排队等待和电源偏好。没有测量数据时默认使用通过试跑的“软件解码+硬件编码”，对短片与重滤镜保守选 CPU，记录理由；后续用同类任务实测改善估计，不靠型号白名单猜倍速。禁止为选卡自动遍历用户全部媒体做长时间基准。

用户手动锁定设备时仍执行能力检查。多显卡任务固定到选定 adapter，不在运行中改设备；重试可以建立新计划。驱动更新导致缓存失效并不改动正在运行的 attempt。

## 调度与资源预算

初始默认总转码并发 1、每硬件适配器编码并发 1、软件重转码并发 1、probe 并发 2、缩略图并发 1、完整验证并发 1。上述后台活动共享预算，转码繁忙时缩略图与主动硬件测试降优先级。用户可将总并发配置为 1–4，但不会突破后端已验证上限。

调度令牌包含：全局转码槽、CPU 重负载槽、adapter 编码槽、I/O 目标组槽、验证槽。获取顺序固定，获取失败回滚已持有令牌，避免死锁；每个 attempt 唯一持有，结束必释放。UNC 或同一外置盘默认串行写入；驱动会话被其他应用占用时仍可能失败，不能因应用槽空闲就认为一定可启动。

队列 FIFO，允许未运行任务重排；资源不匹配时可运行后续兼容任务，但为等待任务保留老化优先级，避免饥饿。降低并发不杀在途任务。禁止用 FFmpeg 的 `-threads` 当 GPU 会话控制；软件线程数、解码线程、滤镜线程需独立设置并用基准校准，默认由核心合理分配且并发保守。

电池模式默认“节能”：并发 1、禁止主动长基准，已运行任务继续；用户可选性能优先。编码会话期间申请防系统空闲睡眠的执行请求，完成即释放；不阻止用户手动睡眠，也不默认保持屏幕常亮。不依赖不可用的温度传感器；监测数据获取失败时界面写“不可用”。

## 回退边界

自动模式且允许回退时，每个 job 最多一次自动重跑，候选按计划记录，典型为 GPU 全链 → CPU 解码+GPU 编码或 CPU 编码。不能在已有输出中途换编码器。失败 attempt 先终止并清理，创建新临时路径，UI 明确“从头重试”。

仅设备初始化、硬件格式/滤镜路径、会话耗尽等能力类错误允许候选回退。磁盘满、源损坏、权限、参数编译错误不应换 GPU 重跑。无法可靠归类时标未知失败，交用户重试；本地化 stderr 关键词不能作为唯一依据。相同 core/driver/capability 的重复硬件失败熔断本会话，用户重测可恢复。

## 性能预算（目标，尚未实测）

基准机 R1：Windows 11 x64、6 核及以上近代 CPU、16GB RAM、NVMe、1080p SDR H.264 样片；记录实际型号/电源/驱动。硬件分机按后端另列。

| 指标 | 初始验收目标 | 测量边界 |
|---|---|---|
| 冷启动至可操作工作台 | p95 ≤3 秒 | 已安装依赖、不含首次安装，10 次记录 |
| 热启动 | p95 ≤1.5 秒 | 同机器同版本，10 次 |
| 点击/导航响应 | p95 ≤100ms | 从输入到下一帧可见反馈，不等 probe 完成 |
| 导入反馈 | ≤200ms | 显示占位/枚举计数，非全部读取结束 |
| UI 推送 | 每活动任务最多 4Hz | 终态立即；FFmpeg 进度建议 2Hz |
| 空闲 App 私有工作集 | ≤180MB | 不含 FFmpeg 与系统共享页 |
| 1000 队列元数据后 App 工作集 | ≤350MB | 缩略图有界缓存、列表虚拟化 |
| 取消确认后子进程清理 | p95 ≤3 秒 | 本地固定盘；超时有故障记录 |
| 转码封装调度开销 | 中位耗时 ≤同参数裸 FFmpeg 的 1.05 倍 | 不含附加验证，长片 ≥60 秒，多次对照 |

达不到预算时先定位再更新目标理由，不能删验证来美化编码速度。硬件性能报告同时记录耗时、平均/峰值内存、输出体积、错误、质量指标；PSNR/SSIM/VMAF 可作辅助但不能跨不同裁剪/尺寸/帧数直接比较，也不替代视觉抽查。默认版本不能写“速度提升 X 倍”，除非附可复现配置与质量条件。
