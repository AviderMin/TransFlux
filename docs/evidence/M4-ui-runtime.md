## Layout fix — 2026-10-31 (after studying D:\Projects\Github\SurgeLink)

The first build's main window had overlapping/mis-sized elements. Root causes were found by
measuring live UI Automation bounding rectangles (the executing model cannot view screenshots), then fixed:

1. **Flex ignored**: page/shell roots used `VStack`/`HStack` (WinUI `StackPanel`), which ignore the
   `.Flex(grow)` modifier. Content was never height-bounded, so the tall right settings panel ran past the
   window and the header row clipped (`查看详情` was 7 px wide). Replaced with Reactor's Yoga
   `FlexColumn`/`FlexRow` and nested `Grid` (`GridSize.Auto/Star/Px`), matching SurgeLink's shell pattern.
2. **Navigation pane overlay**: `NavigationView.PaneDisplayMode = Auto` entered an overlay mode; the pane
   sat on top of the content and a full-window dismiss scrim appeared. Forced `PaneDisplayMode = Left`
   (docked, content offset) and hid the built-in duplicate Settings item.
3. **Settings column**: given a fixed 380-DIP track via Yoga `Flex(basis: 380, grow:0, shrink:0)` and a
   vertical `ScrollViewer` (`HorizontalScrollMode = Disabled` so text wraps). Header action buttons moved to
   their own row so they no longer clip at 150% DPI.

Verified live (150% DPI, logical ~1000 DIP window):

| Element | Before | After |
|---|---|---|
| 查看详情 button | x=692,w=7 (clipped) | x=641,w=79 (full) |
| Settings pane width | 569 px unconstrained, overflowing | 569 px = 380 DIP fixed track, vertical scroll |
| Nav pane vs content | overlaid (content x=235 under pane 132–448) | docked; content starts x=417 after pane |
| Full-window dismiss overlay | present | none |

All four pages (转换/任务/预设/设置) re-measured: every control now sits inside the window bounds with no
sibling overlap. Screenshots: [convert.png](screenshots/convert.png), [queue.png](screenshots/queue.png),
