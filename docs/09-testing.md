# 09 · 测试、基准与发布验收

## 验证原则

测试应验证用户可见语义和失败不变量，不只断言参数字符串与实现一致。使用真正固定的 FFmpeg 核心做集成测试，单元测试用于规则与调度。本文是测试计划，当前无应用代码，未执行这些测试。

## 测试层次

| 层次 | 重点 | 通过证据 |
|---|---|---|
| Domain 单元 | 有理数、裁剪、兼容矩阵、流选择、路径名规则 | 输入/预期表、关键不变量 |
| Application 单元 | 状态机、取消竞态、回退次数、领取、令牌回收 | 可控时钟/假 runner，重复事件与乱序事件 |
| Engine 集成 | 真 probe、转码、滤镜、元数据、验证 | 输出 probe、样片解码、源哈希 |
| Persistence 集成 | migration、WAL backup、提交 journal、断电恢复 | 故障注入点和恢复结果 |
| Windows 集成 | Job Object、路径、文件锁、picker、MSIX | Windows 实机或 VM 报告 |
| UI 自动/人工 | Reactor 组件、焦点、虚拟化、主题、键盘 | UIA 流程、截图、Narrator 记录 |
| Hardware 实机 | NVENC/QSV/AMF、双 GPU、会话竞争 | adapter/driver/core/config 明细 |
| Performance | 启动/交互/内存/吞吐/稳定性 | 原始数据、分位数、对照命令 |

## 样片目录规范

`tests/media-manifest.json` 在编码阶段创建，记录 sampleId、来源/生成脚本、授权、hash、流描述、目标用例、预期输出。优先 FFmpeg 生成 testsrc/sine 和自制获授权样片；不把私人媒体或未经授权影片提交仓库。小文件可提交，大文件脚本生成且记录核心版本；损坏样本从生成媒体按固定位置截断。

必须包含：

- S01：1080p SDR BT.709 H.264/AAC 30fps，60s；基本 CPU/GPU 路径。
- S02：竖屏 rotation 90°、非方形 SAR、奇数显示尺寸分别独立样本。
- S03：VFR、29.97 有理帧率、非零 start_time、音视频 offset 各一例。
- S04：无音轨视频、仅音频、封面附图、多视频、三音轨/default/language。
- S05：SRT/ASS 文本与位图字幕、章节、自由元数据、附件。
- S06：10-bit HDR10、Dolby Vision 标识、未知色彩；验证阻断与白名单。
- S07：损坏/截断、零字节、伪扩展名、超短/未知时长；验证隔离。
- S08：4K 长片性能样本、至少 30 分钟稳定性文件或生成方案。
- S09：中文/emoji/空格/`&` 路径、同名、长路径、只读、硬链接、重解析点。
- S10：5.1 音频、采样率变化、AAC priming；验收声道顺序/同步。

容器、字幕与色彩不在支持矩阵时测试预期为明确拒绝，不能为让样片通过偷偷扩大承诺。

## 硬件测试矩阵

CPU-only 是所有 CI/可发布包的最低功能门槛。NVENC、QSV、AMF 各至少一台真实机器，记录代际、driver、系统和能力族；双显卡至少一次明确验证 LUID→后端设备映射，远程桌面/设备禁用后确认可降级。不具备硬件时测试标记 **未执行**，可以关闭该后端后发布受限预览，不能使用 mock 代替“已支持”。

对于开放的 GPU 全链，每个包含 resize/trim/pix_fmt 的路径单独测。CPU decode + GPU encode 通过不能替 GPU decode + GPU filter + encode 签收。会话被其他应用占用、显卡移除/驱动 reset 的错误测试优先用可控模拟和安全实际条件，不做破坏性驱动操作。

## 性能测量办法

1. 固定样片、core hash、命令、输出盘、电源档、CPU/GPU 型号、驱动、OS 和 App build。
2. 分别记录冷/热启动；每组 10 次，保留原始数据与 p50/p95。耗时长的转换每组至少 3 次，报告中位数和范围，不伪造有意义的 p95。
3. 转换对照为同计划同参数裸 FFmpeg；分别报告编码耗时、验证耗时、提交耗时与端到端耗时。
4. 比较硬件与 CPU 要同时给出档位、体积、画质抽检/可用指标；不能用不同画质说明硬件必然更快。
5. 用 Event/ETW 或适合的 Windows 工具记录 UI 响应、私有工作集、CPU/视频引擎与 I/O；获取失败标未知，不显示 0%。
6. 连续跑 100 项或 8 小时，检查峰值/结束后内存、句柄、进程、残片、数据库完整性。长期任务允许资源波动，不允许无界缓存或持续泄漏。

## 发布报告模板

`docs/evidence/<milestone>-<date>.md` 至少包含环境、commit、精确依赖、命令/脚本、样片 hash、通过/失败/未执行列表、性能原始数据链接、截图、缺陷、复现步骤。发布时附需求 ID 覆盖表；P0 阻断缺陷为 0，已知问题逐项说明实际影响。测试命令必须是项目真实可执行命令，不能照抄此计划当测试完成证明。
