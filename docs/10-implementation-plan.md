# 10 · 实施路线与任务拆解

## 执行原则

先打通一个真实的 SDR 文件从 Reactor 窗口到安全输出的纵向切片，再扩展批量与硬件。每个里程碑必须能构建、运行、演示与回滚；不先生成全部页面空壳、几十个未实现接口或 mock 进度。里程碑按结果排序，不承诺未经人力评估的工期。

## M0 · 技术基线与风险消除

| 任务 | 内容 | 验收产物 |
|---|---|---|
| M0-01 | 查 .NET/Windows SDK/WinApp 工具链；固定 Reactor、模板、Windows App SDK 组合 | `global.json`、精确包版本、版本矩阵与来源 |
| M0-02 | 用官方模板建立最小 Reactor WinUI 窗口 | 原生窗口截图、完整 build/run 命令；无替换框架 |
| M0-03 | 验证 NavigationView、虚拟列表、文件选择器、主题与 effect 清理 | 实际组件样例、订阅无重复、键盘可用 |
| M0-04 | 固定可信 FFmpeg/ffprobe 工具包并核对 GPL 路线 | hash、version/buildconf、编解码器与许可材料差距 |
| M0-05 | 验证 Job Object 受控启动、进度与取消 | 强杀 App 不遗留 ffmpeg、含特殊字符路径样例 |
| M0-06 | 验证 MSIX 子进程、路径和自包含运行 | 干净测试系统离线启动证据 |

M0 门禁：Reactor 不能运行、关键原生控件无法承载、核心许可不可解决或 MSIX 无法安全启动核心时，记录阻断与复现，向用户给出具体方案；不能跳过直接换技术。版本锁定时上游 `main` 文档不是二进制 API 的权威替代，必须对照对应 tag/commit。

## M1 · CPU 纵向切片

依赖 M0。创建 Domain/Application/Engine 最小边界；实现单文件 probe、固定通用视频 preset、typed plan、CPU libx264 转码、真实进度、取消、验证、同卷临时输出与 no-replace 提交。Reactor 工作台能选择文件、显示摘要、执行、定位输出和显示错误。

验收：T02/T06 基础/T10/T14/T18；源 hash 不变；fake runner 只用于测试，演示必须用真实核心。此阶段先不做复杂 GPU、预设导入和漂亮统计图。

## M2 · 可靠批量与持久化

依赖 M1。实现 SQLite 迁移、request 快照、Job/Attempt 状态机、提交 journal、重启恢复；有界导入/probe、队列排序/暂停/重试、批量选择与覆盖；诊断日志与脱敏导出。落实单实例与第二次激活导入策略。

验收：T01/T03/T07/T10–T15/T19。应用崩溃点覆盖 Running、Verifying、Prepared、rename 后落库前；有序领取与令牌回收可复现。

## M3 · 硬件路径与调度

依赖 M2。实现 DXGI 设备枚举、FFmpeg 编译能力查询、主动试跑、缓存、适配器映射、NVENC/QSV/AMF 后端；候选选择、自动回退与熔断、手动设备锁定、电池策略、资源令牌。先软件解码+GPU 编码，再逐条开放完整 GPU 链。

验收：T08/T09 与真实机器性能报告。没有实机的 backend 标未验证并关闭；所有已启用后端有资格矩阵与质量档说明。GPU 指标无法读时仍可完成转换，不让监控成为依赖。

## M4 · 完整 P0 产品体验

依赖 M2，硬件组件与 M3 集成。实现 M4A/FLAC/WAV、白名单转封装、多音轨/文本字幕的受约束支持、单段裁剪、缩放、预设另存/导入、历史、设置、语言资源、主题、可访问性与窄窗口。

验收：FR-01～15 全覆盖，T04/T05/T06/T15/T16/T17；四个主要页面均真实 Reactor 实现。UI 审查截图覆盖 03 所列状态；不以截图代替键盘和读屏实测。

## M5 · 性能、打包和交付

依赖 M3/M4。完成 06 性能预算测量、100 项/8h 稳定性、长路径/UNC/磁盘异常、签名 MSIX 安装/升级与迁移、依赖安全检查、SBOM/第三方材料、已知问题和最终交接。

验收：09 全部适用用例有结果；无法通过的 P0 不隐藏，修复或经用户明确调整范围。任何“支持某 GPU”“离线可用”“无损”“性能优秀”的宣称都链接到证据。

## 每个任务的完成定义

代码符合模块依赖；对可见行为完成有意义验证；错误/取消路径可用；没有悬空订阅与进程；相关文档同步；干净构建通过；报告列出执行命令、结果、未验证事项。不能把 TODO、抛 `NotImplementedException` 或死数据按钮算完成功能。

## 推荐决策节奏

不阻塞的实现细节由编码者自行决定并记录：类名、目录细化、测试工具选择、日志库等。框架替换、默认许可路线、源文件安全、质量默认值的大改须给出证据与影响，交用户决策；先完成可复现原型与具体方案再请求选择。

首次编码只执行 M0，完成后根据实际工具链完善本计划。每阶段保留简洁证据，不为追求表面覆盖重复创建相同测试；优先用已知失败样片和真实竞态验证关键不变量。
