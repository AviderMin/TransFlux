# 01 · 项目定调

## 产品定位

TransFlux 是本地优先的 Windows 桌面媒体转换工具，服务需要批量处理视频、音频、调整体积或兼容格式的普通用户与轻度创作者。核心价值是少量决策完成可靠转换，同时让高级用户看到真实参数与执行路径。

一句话定位：**原生 Windows 操作体验，懂硬件的可靠媒体转换。**

优先级依次为：源文件与输出安全 → 媒体语义正确 → 主流程易用 → 在质量约束内提高性能 → 扩展能力。不能以 GPU 占用高、漂亮动效或更多格式掩盖错误转换。

## 不可变原则

- **Reactor 是界面核心。** 使用微软 `Microsoft.UI.Reactor`，不是 Rx.NET、React Native、MauiReactor 或同名 Rust 库。主窗口、导航、转换工作台、任务队列、预设、设置均由其 C# 组件构建；允许局部原生互操作，不允许主体回退到 WPF、WebView、Avalonia 或 XAML MVVM。
- **先用途后参数。** 用户先选择“通用视频、节省空间、提取音频、只换封装”，再按需展开编码细节。
- **硬件为体验服务。** 自动策略解释为什么选择 CPU/GPU；硬件失败不丢任务，降级必须可见且遵守质量约束。
- **性能是测量结果。** 对启动、响应、吞吐、内存和稳定性分别验收；不承诺跨硬件的固定倍速。
- **本地完成。** 不要求账号，不上传媒体，不依赖云端转换；首次启动不自动下载核心或驱动。

## 首发边界

首发为 v0.1 可验收预览：Windows 11 22H2（build 22621）及以上 x64。此平台下限是产品选择，仍须在 M0 核验所选包组合；不能据此宣称所有 WinUI 应用都具有相同下限。支持中文简体和英文资源、系统/浅色/深色主题、DPI 与键盘操作。

视频：MP4/MKV 输入为重点测试集合，其他本地格式按核心探测结果接受。输出重点为 MP4 H.264/AAC、MKV H.264/AAC、音频 M4A AAC/FLAC/WAV、受约束的无损转封装。HEVC、AV1 与更多编码器列 P1，不以“探测到名称”作为首发可用保证。

首发硬件编码路线为 NVENC、QSV、AMF 三类 H.264 适配器；软件解码配硬件编码可以作为首发稳定路径。GPU 解码和全 GPU 滤镜链在有证据时启用，未验证的组合关闭。CPU 必须有可运行基线。

首发仅支持 SDR 普通文件转换。检测到 HDR、Dolby Vision、复杂色彩或动态元数据时，禁止自动走 SDR 转码；展示说明并允许在满足兼容矩阵时转封装。P1 才引入经样片验证的 HDR 保留/色调映射。

## 非目标

首发不做时间线编辑器、云盘、视频下载器、流媒体服务器、DRM 处理、AI 超分、插件市场、实时直播、多机器集群、光盘菜单、自动关机或任意命令行编辑器。不实现运行中暂停/续传编码；“暂停队列”只停止启动后续任务。

## 核心决策

| 主题 | 定调 |
|---|---|
| UI | 原生 WinUI 3 + C# Microsoft.UI.Reactor，组件 + 单向状态流 |
| 核心 | 首发 FFmpeg/ffprobe 独立子进程；以窄接口隔离实现 |
| 包装 | 不依赖大而全 FFmpeg .NET 封装；自行实现类型化命令编译和进程控制 |
| 数据 | SQLite 保存队列、历史、预设；进度不逐帧落盘 |
| 分发 | 应用 MIT；媒体核心单独列明构建与许可，默认候选为 GPL FFmpeg 工具包 |
| 基线编码 | 候选 CPU `libx264` + 原生 `aac`；因此不能声称默认核心为纯 LGPL |
| 安装 | 首发签名 MSIX x64，应用与核心均离线可用；便携版后续评估 |
| 质量 | 默认“均衡”，分编码器独立标定，禁止将 CRF 数字直接套到硬件编码器 |
| 调度 | 默认总转码并发 1，硬件每适配器会话预算 1；测量后才提升 |

许可证路线是工程提案而非法律结论。二进制分发、源代码提供与商业分发条件在发布前按实际构建核验；独立进程不是自动免除义务的依据。

## 成功指标与取舍

默认单文件流程：拖入 → 选用途 → 点转换，输出目录默认源目录下 `TransFlux Output`。无权限则在开始前引导选择；不静默换目录。常规转换无需打开高级设置，失败提示必须提供下一步动作。

不以输出更小、画质无损作为无条件承诺。界面明确“编码会改变画质”“预计大小有误差”；只有流复制路径称为“无需重新编码”，也不保证容器元数据逐字节保留。

若 Reactor 缺少关键包装器，优先补局部适配器并测试生命周期。若框架导致阻断，提交可复现问题和备选方案供用户决策，不能换框架后继续声称完成。
