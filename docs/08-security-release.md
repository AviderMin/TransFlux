# 08 · 安全、可靠性与发布

## 进程与输入

- 使用绝对可信核心路径，`ProcessStartInfo.ArgumentList`，`UseShellExecute=false`、`CreateNoWindow=true`；不经 PowerShell/cmd 拼接执行用户文件名。
- stdout 用于结构化进度，stderr 用于有界日志，二者并发异步读取防止管道死锁。Probe JSON 与日志都限制输出大小，超过上限分类失败。
- 子进程纳入 Windows Job Object，设置 KILL_ON_JOB_CLOSE。为消除进程启动后关联 Job 的窗口，优先使用受控原生启动器：挂起创建→加入 job→恢复；若采取其他方式，提交取消/崩溃无孤儿进程的证据。关联失败时终止该进程并报告，不允许失管运行。
- 取消直接终止 attempt 的 job/process tree，再等待退出并回收 handle。`-nostdin` 模式不发送 `q`。异常结束输出不会发布，允许短暂显示“正在清理”。
- 只接受本地/UNC 文件路径，禁用网络输入协议与不需要的 demuxer；拒绝首发范围外的 playlist、concat、外部引用型输入，降低间接访问其他文件的风险。协议白名单不是完整沙箱，FFmpeg 仍处理不可信二进制数据，需维护安全更新。
- 路径含空格、中文、emoji、引号、`&` 等都通过参数列表处理；滤镜路径另有 FFmpeg 自身转义规则，不能认为 ArgumentList 可处理 filter graph 内部语法。首发 typed filters 不接受用户自由路径文本。

Windows Job Object 可以统一管理并终止进程组；KILL_ON_JOB_CLOSE 的行为来自系统 API，仍需验证 handle 继承和生命周期。[Microsoft Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)

## 输出保护协议

1. 规范化输入/输出并检查文件身份；不能只用字符串相等判断源与目标，需防大小写差异、硬链接和重解析点别名。
2. 输出默认在源旁 `TransFlux Output`，预检写权限与磁盘可用空间。格式化输出名去掉非法字符、保留设备名、尾部点/空格，控制路径长度；用户看见最终路径。
3. 为目标名创建应用预留记录和 `CreateNew` 锁文件；目标在最后提交时仍必须 no-replace，锁只能协调本应用，不能阻止其他程序。
4. 临时输出放目标同卷、按 attemptId 隔离的 `.transflux-work/<attemptId>/` 中，显式 muxer；不预创建同名输出文件再传给带 `-n` 的 FFmpeg。
5. FFmpeg 退出后完整执行验证。取消/失败只删除该 attempt 清单内的文件；删前校验绝对路径在对应工作目录且不是 reparse escape，不使用全盘通配清理。
6. 记录 commit_journal：`Prepared`（临时/最终路径、身份、大小、必要时 hash）→ 执行同卷不覆盖 rename → `Published` → 持久化 OutputRecord 与 Succeeded，完成 journal。
7. 若进程在 rename 后落库前崩溃，启动扫描 Prepared/Published；验证最终文件与 journal 身份后补记成功。临时与最终冲突、身份不符时 NeedsAttention，不擅自删除或认领未知文件。
8. UNC/特殊文件系统不能假设 rename 的原子与持久性。提供明确网络输出提示，先写网络同目录隐藏临时名再改名并回读验证；提交异常 NeedsAttention，保留恢复线索。没有验证的平台不承诺崩溃原子性。

正式文件名冲突默认递增编号；提交时发生新冲突，在状态机内重新预留新名并记录，绝不打开覆盖模式。源文件永远只读，不支持“转换后删除源文件”。失败残片默认在进程确认退出后清理；诊断保留 stderr、计划与验证信息，不默认保留大残片。用户要求保留诊断文件时也放隔离目录。

空间预检：有可信码率估计时要求估计值+10%（至少额外 256MB），无可靠估计时显示未知与当前空间，用户确认后允许执行；过程监测空间只用于尽早失败，不保证不被其他进程抢占。MP4 faststart 等可能增加 I/O/临时空间，要计入测试和提示。

## 隐私与数据生命周期

默认无遥测、无在线检查、无媒体上传。历史默认最多 1000 项或 90 天（先到为准），普通滚动日志最多 14 天/100MB，缩略图缓存最多 256MB；活跃任务、提交恢复记录和用户预设不参与普通清理。历史与日志分别可清除，清除记录不删除输出。

诊断导出前展示摘要：核心版本、OS/驱动、路径脱敏、选定 job 参数、错误尾部。用户文件名、用户名、UNC 主机等默认脱敏为映射别名；仅去掉用户名不足以保护文件名隐私。明确选“包含原始路径”才输出；不自动发送任何报告。

## 许可与供应链

应用仓库当前 MIT 保持不变。FFmpeg 总体许可受构建选项和依赖影响；启用 GPL 组件会改变核心分发义务，`--enable-nonfree` 构建不能当默认可再分发版本。许可判断需依据实际二进制与依赖，不用进程边界推断免责。[FFmpeg 官方许可说明](https://svn.ffmpeg.org/legal.html)

默认候选为包含 `libx264` 的 GPL FFmpeg 工具包，不能一面默认 CPU libx264 一面宣称 LGPL-only。M0 记录候选来源，发布门槛记录其许可证版本、源码获取方式、完整构建脚本/配置、所有补丁、第三方库清单与版权声明，按对应要求提供源码。应用 MIT 与聚合分发的相互关系需完成实际材料审阅，本文不替代法律结论；未完成不得公开发布安装包。

发布目录应包含 `THIRD-PARTY-NOTICES`、license 文件、源码归档/有效提供方式、SBOM、组件 hash manifest。核心须能重建或溯源，使用第三方 Windows build 时验证可信来源、哈希及其源码材料；不能把“FFmpeg 官网页面链接”当作该特定构建的源码交付。

签名/哈希保证来源与完整性，不代表软件无漏洞。维护依赖安全更新清单，升级核心重跑 probe、命令、质量与能力矩阵，不悄悄换构建。

## 安装、更新与兼容

首发选择签名 MSIX x64，捆绑已验证媒体核心，.NET 与 Windows App Runtime 采用实测支持的自包含组合，确保干净 Windows 测试机离线可运行。如果大小/打包能力导致改为框架依赖，必须修改本条并提供离线依赖包与明确安装顺序。打包目录只读，数据库、日志和临时媒体不得写入安装目录。

版本格式应用 SemVer；数据 schema 单独递增。CI 包含锁定 restore、Release 构建、单元/集成检查、许可证/哈希生成；签名密钥不进仓库。先发布内部测试包，再预览版。P0 不实现自定义在线更新器，使用外部分发/系统安装更新渠道；更新前要求无活动任务，迁移前做备份。旧版本无法理解新 schema 时阻止降级打开并指导恢复，不能破坏性回滚。

干净虚拟机验证首次安装、升级、修复、卸载、数据保留规则与离线启动；物理机验证驱动与 GPU。不默认管理员权限运行。ARM64、x86、Windows 10 不在首发承诺内。

## 发布门禁

必须具备：可复现版本清单、全部 P0 验收通过、每个公开硬件后端有实机证据、无源文件破坏/孤儿进程/错误成功状态、DPI/键盘/主题检查、性能报告、签名安装验证、核心许可材料、已知问题和交接总结。没有验证的后端在发布包中禁用或明确实验开关，不能包装成已支持。
